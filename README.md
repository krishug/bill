# 批量发票图片识别与 Excel 导出工具

Windows 10/11 桌面工具：本地处理 JPG、JPEG、PNG 图片和 PDF 发票，依据票面文字及位置提取字段、逐页校验，供人工复核后导出 `.xlsx`。文件夹模式递归查找子目录，图片和 PDF 可混合；支持多页 PDF，损坏/加密文件或单页出错不会中断其他任务。

## 当前能力

- Tkinter 图形界面：选择多个图片/PDF 文件或递归扫描目录、设置 Excel 路径、开始/取消任务、按图片/PDF 页显示处理进度。
- 主表字段顺序为“序号、发票号码、金额、税额、价税合计金额、销售方公司名称”；PDF 行保存原文件名、页码。选择复核记录可查看图片或对应 PDF 页及文字原文，并人工修正发票号码和金额字段。
- PaddleOCR 中文 PP-OCRv4 本地 CPU 推理，保留每个 OCR 文本框、位置及模型返回的原始文本置信度；不合成“字段置信度”。首次运行会下载模型到用户目录下的 `.paddleocr` 缓存。
- PDF 优先逐页直接读取 PyMuPDF 的文本层及 PDF 坐标；只有文字缺字段、关系不明确或校验冲突时才渲染该页并尝试现有 OCR。扫描页按 144 dpi 渲染，一页处理完即释放图像内存。混合 PDF 按页选择文字层或 OCR。
- 发票号码只从“发票号码”标签后的票面文本提取，保留为字符串（含前导零）；仅接受常见的 8 位或 20 位数字格式。没有标签、位数异常、低置信度或存在多个号码时留空并标记复核，不会从文件名、序号或纳税人识别号猜号。
- 同一 PDF 中号码、销售方及可用辅助字段匹配的多页记录会合并页码，避免续页重复录入。页面含多个不同号码/多张票或无法确定边界时不会自动拆分/合并字段，会留空关键字段并标记待复核。跨文件疑似重复会保留所有记录，依据发票代码、销售方、日期等可用信息提示人工核对。
- 方向判断：对文字框方向明显异常、或首轮内容不足的图片尝试 90°/180°/270°，同时保留原图坐标和校正后的版面坐标。
- 校验缺失字段、金额加税额与价税合计差异。价税合计低于金额加税额（含 0.01 元）会待复核；高于金额加税额超过 0.01 元也会待复核。缺失税额不等同于 0；仅票面明确出现“免税/不征税”时将税额作为 0。负数按原值校验，不自动覆盖票面金额。
- Excel 至少包含“发票明细”“异常复核”“处理统计”三个工作表，并附加“OCR原始内容”表保存原文、来源页码、坐标框及 OCR 行置信度；纯 PDF 文本没有 OCR 分数时保持空值。发票号码作为文本保存；金额为数值类型并显示两位小数；冻结首行、筛选、调整列宽；图片/PDF 路径可点击定位；人工修正或云端补识别后仍保留初次本地识别字段。
- 可选 OpenAI-compatible 视觉接口仅对存在字段问题或识别失败的所选记录开放，并且每张图片上传前都需要单独确认。云端结果仍经过本地校验。

**识别结果需要人工复核。** 发票版式、拍照遮挡、清晰度和 OCR 模型表现都会影响字段解析；程序不会用“金额 + 税额”计算结果填补缺失的票面字段。方向判断目前处理直角旋转，不承诺修复任意角度倾斜、严重模糊、遮挡或非标准票种。PDF 若出现无法可靠判断的单页多票/跨页边界，会留待人工处理。

## Windows 安装与启动

已实测环境：Windows 10 x64、CPython 3.11.9；Python 自带 Tkinter 8.6。依赖版本固定在 `requirements.txt`，包括 `PyMuPDF==1.25.5`。本目录的原始图片、PDF 及已有 Excel 不会被启动脚本覆盖；`.gitignore` 排除这些敏感文件、`.env`、缓存、模型和虚拟环境。

1. 安装 **Python 3.11 x64**，安装时勾选添加到 PATH。
2. 从 GitHub 克隆源码：`git clone https://github.com/krishug/bill.git`，然后进入 `bill` 目录。双击 `start.bat`；脚本创建独立 `.venv`、安装固定依赖并启动图形界面。
3. 首次本地 OCR 会从 PaddleOCR 官方模型源下载中文检测/识别模型；纯文字电子 PDF 在字段齐全时直接本地解析，不需要 OCR 模型下载。模型准备后图片/PDF 本地功能可离线使用；安装依赖、首次模型下载和可选云端识别需要网络。
4. 选择多个图片/PDF 文件，或选择含混合文件的文件夹（递归扫描），指定输出 `.xlsx` 并开始识别。
5. 处理完成后筛选“待复核”记录，选中记录查看图片/PDF 页和原文并修正，最后导出 Excel。

启动脚本和自动化测试也可分别在终端运行 `start.bat`、`.venv\Scripts\python.exe -m pytest -q`；日常识别不需要命令行。

## 可选云端识别

默认没有 Go/API key 时云端功能关闭，本地 OCR 完全独立可用。OpenCode Go 可使用官方列出的视觉模型 `deepseek-v4-flash-vision-exp` 和兼容 endpoint。可以复制 `.env.example` 为 `.env`，填入你的 OpenCode Go API key：

```bat
copy .env.example .env
notepad .env
```

在 `.env` 中填写 `OPENCODE_GO_API_KEY` 的值，保存并启动 `start.bat`。程序会读取项目目录下的 `.env`；该文件已加入 `.gitignore`，不会随源码提交。也可以在启动前设置同名 Windows 环境变量；进程环境变量优先于 `.env` 配置。

Go 默认使用 `https://opencode.ai/zen/go/v1` 和上述 vision model，并发送专用 User-Agent 及稳定的 `x-opencode-session` 会话标识。其他 OpenAI-compatible 视觉服务可在 `.env` 中配置 `INVOICE_VISION_API_KEY`、`INVOICE_VISION_BASE_URL`、`INVOICE_VISION_MODEL`。工具不会读取 OpenCode GUI/TUI 登录状态。**配置密钥不会自动上传图片**：必须选中字段有问题或识别失败的记录、点击云端按钮并确认具体文件后才发起请求。

OpenCode Go 官方文档将服务定位为 coding-agent 请求；通过它做发票图片提取前，请确认该用途符合服务当前条款和模型额度。由于没有配置你的 Go key，本项目只验证了本地 OCR 和云请求构造，未对 Go 服务发起真实图片请求。

## 自动化测试与识别率评估

```powershell
.\.venv\Scripts\python.exe -m pip install -r requirements-dev.txt
.\.venv\Scripts\python.exe -m pytest -q
```

自动化测试覆盖票面号码严格提取/前导零/税号防误识、缺失字段、金额差异、重复辅助字段判断、文字型/扫描型/混合型 PDF、逐页定位、续页去重、多票边界、递归文件夹、损坏和加密 PDF 不中断批次、Excel 列顺序及数据类型、云端配置和请求格式。OCR 场景夹具验证解析与校验逻辑；这些模拟用例不替代真实票面的人工准确率基准。

已执行测试、现有样例逐字段对照和限制记录见 [`TEST_REPORT.md`](TEST_REPORT.md)。

要测真实字段正确率，请逐张人工确认图片/PDF 页结果，填写 `benchmark/ground_truth.template.csv`（`filename` 和 `page_number` 须对应识别结果中的原始文件名和页码），并将识别输出工作簿与标注 CSV 一起传给：

```powershell
.\.venv\Scripts\python.exe benchmark\evaluate_accuracy.py 人工标注.csv 识别结果.xlsx
```

脚本按字段统计严格匹配数/人工标注数。只有经人工确认的票面字段才应写进 ground truth；请结合模糊/倾斜、缺失字段、计算差异、红字负数、重复号码、无效图片和多个金额易混淆等样例检查结果。

## 常见问题

- **启动时版本或依赖报错：** 使用 64 位 Python 3.11；确认 `python --version` 为 3.11，并允许首次运行从 PyPI 下载固定依赖。
- **首次本地图片/扫描版 PDF 处理停留较久：** 首次会从 PaddleOCR 官方模型源下载检测、识别模型。检查网络/代理；模型缓存完成后 OCR 可离线运行。纯文本 PDF 字段完整时无需该模型。
- **PDF 提示加密或无法打开：** 加密 PDF 目前不尝试破解或输入密码；请在本机解除保护后再处理。损坏文件会在结果中保留失败原因，不影响其他文件。
- **扫描页结果待复核：** 页面分辨率、遮挡、旋转和多票边界都会影响识别；核对异常表中的文件名/页码、原图和 OCR 原文，再人工修正。跨页/一页多票无法可靠判断时不会自动拆分字段。
- **云端按钮不可用：** 仅字段问题/识别失败记录显示按钮。OpenCode Go 请设置 `OPENCODE_GO_API_KEY` 后重启程序；点击按钮并确认具体页面后才会上传。
